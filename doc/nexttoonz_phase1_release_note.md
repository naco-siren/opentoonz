# 矢量渲染改在 CPU 上：变化说明（草稿）

草稿，2026-11-16，待所有者审阅后再对外发布。计划（`doc/nexttoonz_plan.md` Phase 1）要求"人工审图确认矢量外观变化可接受，并发布说明"，这是那份说明。技术细节在 `doc/nexttoonz_canvas_ir.md`。

## 变了什么

渲染输出里的矢量内容不再由 OpenGL 画，改由 CPU 上的光栅化器（Skia）画。涉及：

- 命令行渲染（tcomposer）和应用里的渲染、预览：矢量层、默认粒子、图案样式的源帧，以及 plastic 变形和流动笔刷两个特效。
- 矢量转色指定栅格（tlv）、往栅格上加笔触、剪贴板与直方图用的矢量图、样式色块、关卡图标、导出关卡、追踪、生成网格。
- 场景图标、xsheet 缩略图和打印。

不变的：

- 编辑时的 viewer 窗口（摄影表视图、工具、洋葱皮、3D 视图）仍用 OpenGL，画出来和以前一样。
- 栅格层、色指定栅格层，以及不含矢量的特效，逐位不变。
- GLSL 着色器特效（ShaderFx、GPU 特效）仍需要 OpenGL。

## 看起来有什么不同

整体外观保持不变：线的粗细、颜色、位置都和以前一致。差别在边缘一两个像素以内，320x180 的参考场景里，矢量场景每帧有 0.8% 到 2% 的像素与以前相差超过 2 个色阶，集中在矢量的边上。分辨率越高越不明显。具体是：

- **边缘**。以前的反走样是在填充外面再描一圈一像素的平滑线；现在按覆盖率精确计算。斜边和曲线的边缘略有不同，形状本身不变。
- **线重保持原样**。纯色笔触仍比几何宽度每边多半个像素，这是以前那圈平滑线带来的效果；需要时可以用 `NEXTTOONZ_STROKE_GROW=0` 改成按真实宽度画。
- **相邻区域之间不会出现发丝缝**。区域同样外扩半个像素，被后画的邻居和笔触盖住。
- **几个特殊样式有可见的差别**：贴图和颗粒状笔触的纹理采样略有不同；点状阴影的点在 Linux 的软件 OpenGL 上被放大四倍，现在是设定的大小；半透明排线互相重叠处颜色略淡；硬边图案（方格、条纹等）仍是硬边。
- **plastic 变形**：网格外边由覆盖率决定，没有那一圈淡边；变形后的边上偶尔能看到不到一个像素的凸起。
- **流动笔刷**：细长笔尖沿长度方向比以前清楚一些。
- 以前同一个场景在不同显卡上渲染结果可能不同（AMD 驱动的虚线相位、Linux 与 macOS 的填充规则），现在各平台的结果基本一致：普通矢量场景在 macOS 和 Linux 之间最多差 4 个色阶，样式最多的场景最多差 16。

逐场景的对照图：`samples/review/step2/` 到 `step9/`（不在版本库里）。

## 速度

在命令行渲染里通常更快。1920x1080 的参考场景渲染时间是以前的约 1/2 到 1/25，因为不再为每一帧建 OpenGL 上下文、读回像素。只计算画图本身时，在放大很多倍的复杂笔触上 CPU 会慢一些。没有用真实作品量过。

## 怎样回到以前的画法

设环境变量 `NEXTTOONZ_VECTOR_RASTERIZER=gl`，渲染就走原来的 OpenGL 代码，结果与改动前逐位相同。这条退路会保留一段时间。没有编进 Skia 的构建（CMake 选项 `WITH_SKIA` 关闭）也仍然走 OpenGL。
