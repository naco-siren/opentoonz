# NextToonz Phase 2 发布说明（草稿）

Phase 2（核心去 Qt，`doc/nexttoonz_core_noqt.md`）的第 1 到 8 步已合入 `nexttoonz/phase0`；第 9 步起在本地分支 `wip/phase2-step9` 上，没有合并、没有推送。这份说明随步骤补充，发布时再定稿。用户看得到的变化只有下面几条；其余每一步都验证过默认路径不变（渲染、存档、界面文字逐字节相同）。

## 修好的问题

- **tconverter 在 macOS 和 Windows 上能用了**（第 6a 步）。它在这两个平台上从来不建 Qt 应用对象，以前因此把所有路径都当作不存在，什么都转不了。
- **多线程渲染里笔画 id 可能重复**（第 8d 步，已知问题第 33 条）。几个线程同时读关卡时，两条笔画可能拿到同一个 id。现在不会了。过去用 `-nthreads` 大于 1 渲染时偶发的怪现象，可能与它有关。
- **关掉样本查看器以后可能崩溃**（第 9 步，已知问题第 45 条）。专用线程的执行器析构以后，它的线程退出时没有从线程池的表里删掉自己。之后取消图标、取消渲染，以及退出程序时，都可能读到已经释放的内存。现在不会了。
- **存单张图片时的一处数据竞争**（第 9 步，已知问题第 36 条）。几个线程同时存帧时，读伽马标志的那张表没有上锁。现在上锁了，结果不变。

## 行为的变化

- **便携模式多看一处**（第 6c 步）：tconverter 在 macOS 和 Windows 上也检查可执行文件旁边的 `portablestuff`。
- **在应用对象建立之前，文件状态报告真实情况**（第 6a 步）。实测只有 tconverter 在那之前问过。
- **不调 `TThread::init()` 的程序，别的线程发给主线程的消息在发送的线程上立刻执行**（第 9b 步，8.18 节）。以前这些程序（tconverter、tcleanup）根本没有派发器，别的线程上的 `TThread::Message::send()` 会碰到空指针、崩溃；现在能用了。与上面 tconverter 那一条一样，是从崩溃到能用。应用、tcomposer 和农场的程序照旧在 Qt 的事件循环里送达，行为不变。
- **退出应用时等后台线程结束，最多 5 秒**（第 9 步，8.21 节）。以前关掉主窗口时，线程池只通知正在跑的任务停下，不等；后台线程（渲染、图标）可能在程序退出、静态对象析构的同时还在跑。现在等它们结束，等的时候照常处理事件，最多等 5 秒；超过 5 秒照旧退出，并在标准错误上记一行还剩几个线程。命令行程序不受影响（它们不调这个函数）。
